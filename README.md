# SGoTGraph: automatic functional characterization of generated chains of thought

Code and data for the article *Automatic Functional Characterization of Chains of Thought Generated by Reasoning Models* (Becerra-Monsalve, Sanchez-Torres and Branch-Bedoya).

The method represents a chain of thought at two levels. The structural layer is a graph whose nodes are typed segments of the text and whose edges express reading order and semantic relations. The functional layer identifies episodes (progression, verification, correction, support, alternative), each with its outcome, its anchor and its relations to other episodes, groups them into routes and summarizes the chain in a profile. Semantic decisions are made by a language model treated as a measurement instrument; the code validates every decision against the contract of the representation and derives the rest deterministically.

## Layout

| Folder | Content |
|---|---|
| `pipeline/` | The method: nine stages, validators, schemas, the frozen instrument (`instrument_manifest.json`, version `sgotgraph-instrument-2026.14`) and an offline test suite. See `pipeline/README.md`. |
| `RQ1/` | Control corpus with known structure, the pipeline outputs for its 130 chains and the scoring script. |
| `RQ2_RQ3/` | Main corpus (200 chains from four reasoning models on 50 medical and legal problems), the pipeline outputs, two additional runs for repeatability, the per-chain profile metrics and the analysis scripts. |

## RQ1: validity against known structure

- `escenarios/src/*.md`: the 130 chains as written, with their declared episodes, outcomes and relations marked in the text. 204 deliberative episodes are planted (108 with an explicit discourse marker, 96 implicit); 14 chains contain no deliberative episode.
- `escenarios/escenarios.jsonl`: the same chains in the pipeline input format.
- `escenarios/verdad.json`: the declared structure of each chain (episodes, outcomes, anchors, relations).
- `resultados/anotaciones_130.jsonl.gz`: one pipeline output per chain, produced with the configuration described below.
- `resultados/informe_130.json`: sensitivity by type, explicitness and outcome, false positives, relations and routes recovered (Table 5 and Figure 4 of the article).
- `puntuar.py`: the scoring script. A planted episode counts as detected when the pipeline produces an episode of the same type whose text overlaps the planted one with intersection over union of at least 0.5; `condicion_de_paso.json` holds the thresholds it reports.

To recompute the report:

```bash
python RQ1/puntuar.py --corridas RQ1/resultados/anotaciones_130.jsonl.gz --informe informe.json
```

## RQ2 and RQ3: main corpus

- `cadenas_aceptadas.jsonl`: the 200 chains (50 problems × Qwen3.8-27B, Gemma 4 31B, Olmo 3.1 32B Think, DeepSeek V4 Pro), each with its problem statement, options, reference answer, model answer, generation prompt and sampling parameters. The problems come from MedXpertQA (Text, test split) and MMLU-Pro (professional law).
- `seleccion.csv`: the 443 problems tried, the number of words of reasoning each model produced, whether it reached a final answer, and whether the problem was accepted (all four models answered in 4000 words or fewer).
- `resultados/anotacion_200.jsonl.gz`: pipeline output for the 200 chains. `resultados/estabilidad_r1.jsonl.gz` and `estabilidad_r2.jsonl.gz`: two additional complete runs on the 20 chains listed in `estabilidad_ids.json`.
- `resultados/metricas_por_cadena.csv`: the profile attributes of each chain, from which all comparisons are computed.
- `resultados/inferencia_rq2.json` and `tablas_inferencia.md`: negative binomial rate ratios at equal graph size (Table 6). `informe_estabilidad.json` and `estabilidad_grupos.json`: repeatability by layer, ICC per attribute and per-model means across runs (Figure 5). `rq3.json`, `rq3_predicciones.csv`, `rq3_rasgos.csv` and `tablas_rq3.md`: out-of-sample classifiers (Figures 9 and 10).

To recompute, from `RQ2_RQ3/` and in this order:

```bash
python analizar.py            # per-chain metrics from the pipeline outputs
python inferencia.py          # rate ratios (Table 6) and reliability
python estabilidad.py         # repeatability between runs
python estabilidad_grupos.py  # per-model means across runs
python rq3.py                 # classifiers (RQ3)
```

The scripts need numpy, scipy, statsmodels, scikit-learn and matplotlib.

## Annotation configuration used in the article

Both corpora were annotated with the pipeline at instrument version `sgotgraph-instrument-2026.14`, annotator `gpt-6-luna` (OpenAI), three samples per decision for segmentation, typing, edges and episodes (`--consensus-samples 3`), and the edge stage configured with `--edge-payload compact --edge-sources-per-request 6 --edge-candidate-window 24`. The complete command is in `pipeline/README.md`. Every output records its provenance (instrument version, hash of the implementation files and commit), the validation status and the audit of the sampled decisions. The code in `pipeline/` is the one that produced the RQ2_RQ3 outputs; the RQ1 outputs were produced in batches across two minor revisions of the response-parsing code of the provider module, with the same instrument.
